# Contributing to EDR Agent

Thanks for helping. EDR Agent is a **monitor-only** detection project: contributions that keep
it observational (no blocking, killing, hooking, injection, self-protection or system changes)
are very welcome; anything else will be declined.

## Layout

| Path | Language | Build / test |
|---|---|---|
| `agent/` | C++20, CMake, GoogleTest | `cmake --preset dev && cmake --build --preset dev && ctest --preset dev` |
| `server/` | Python 3.11+, FastAPI, SQLAlchemy 2 | `pip install -r requirements-dev.txt && pytest -q` |
| `dashboard/` | React + TypeScript + Vite | `npm ci && npm run lint && npm test && npm run build` |
| `rules/` | YAML | shared by agent and server; see [docs/rules.md](docs/rules.md) |
| `samples/` | JSON lines / XML | generated by `samples/tools/generate_samples.py` |

## Development setup

```bash
# C++ tools pinned for CI (CMake, clang-format, clang-tidy) in a repo-local venv
python3 -m venv .tools && .tools/bin/pip install -r agent/tools/requirements.txt
export PATH="$PWD/.tools/bin:$PATH"          # Ninja comes from your package manager or pip

# Python server
python3 -m venv server/.venv && server/.venv/bin/pip install -r server/requirements-dev.txt

# Dashboard
(cd dashboard && npm ci)
```

## Checks to run before a pull request

```bash
(cd agent && cmake --preset dev && cmake --build --preset dev && ctest --preset dev)
(cd agent && cmake --preset asan && cmake --build --preset asan && ctest --preset asan)
(cd agent && ./tools/lint.sh)                         # clang-format + clang-tidy
(cd server && ruff check . && ruff format --check . && pytest -q)
(cd dashboard && npm run lint && npm test && npm run build)
python3 samples/tools/generate_samples.py --check
```

`server/tests/test_parity.py` runs the C++ binary from `agent/build/dev` (or `EDR_AGENT_BIN`)
and requires identical results from both engines; it is skipped, with a message, when the agent
has not been built.

## Changing the engine

The scoring engine exists twice on purpose (C++ in the agent, Python on the server). Any change
to rule semantics, enrichment or scoring must be made in **both**
`agent/src/engine/` and `server/src/edr_server/engine/`, with tests on both sides; the parity
tests will fail otherwise. Keep arithmetic integer-only.

## Style

- C++: C++20, `.clang-format` (Google-based, 100 columns), `.clang-tidy` clean, warnings as
  errors. Platform code stays in `src/windows/`; everything testable stays portable.
- Python: ruff (settings in `server/pyproject.toml`), type hints, no `eval`/`pickle`,
  `yaml.safe_load` only.
- TypeScript: strict mode, ESLint, accessible markup (labels, roles, keyboard focus).
- Comments explain *why*. Test data uses documentation IP ranges, `example.com`/`example.net`
  and fictional names only.

## Commit messages

[Conventional Commits](https://www.conventionalcommits.org/): `feat: ...`, `fix: ...`,
`docs: ...`, `test: ...`, `refactor: ...`, `chore: ...`.

## Pull request checklist

- [ ] All checks above pass
- [ ] New rules have positive and negative cases in `rule_cases.jsonl`
- [ ] Engine changes are mirrored in C++ and Python
- [ ] README / docs updated if flags, config keys, API or output changed
- [ ] No real telemetry, hostnames, addresses, tokens or credentials anywhere

## Code of conduct

Be respectful and constructive. Harassment or personal attacks are not tolerated.
